两个任务同属 mjlab 框架、同为"前掌倒立行走 + twist 速度跟踪"。基准奖励是一份忠实移植 —— 真正的差距集中在机器人本体、action_scale、姿态几何，以及几处同名异函数的移植暗坑。

Executive summary

00一句话结论

PD 增益 kp/kd 其实完全相同(都 40 / 1.0) —— 这通常是大家以为不同的地方，反而是"假差异"。真正的差距按重要性排序如下。

#1 本体控制
action_scale + 力矩

lite3 把外摆 HipX 缩到 0.125(go2 全 0.25)→ 外摆力矩权威只有 go2 的一半；effort 也是统一 30 vs go2 23.7/35.55。

#2 姿态几何
符号翻转 + 重推导

lite3 三关节轴全反号，关节范围不同，desire 姿态必须重推导(HipY 上限仅 +0.314)，起始更矮(0.30 vs 0.42)。

#3 奖励暗坑
3 处同名异函数

base_height / lin_vel_z / ang_vel_xy 权重相同但函数语义不同，甚至相反。只看权重表会漏掉。

#4 观测空间
lite3 去掉 base_lin_vel

真机不可测，lite3 actor 删掉线速度 → 两者策略观测不兼容，go2 策略无法直接搬到 lite3。

#5 扰动机制
力推 vs 速度推

go2 改用力推(因速度推会秒杀环境)；lite3 base 仍用速度推 → 排查早期不稳定的头号嫌疑。

#6 衍生族
rldeploy ×25

lite3 独有的一整套部署对齐 + Stride-V1…V15 调参族；go2 完全没有对应。

Port artifacts

04移植暗坑 (同名 · 同权重 · 函数却不同)

这是最容易被漏掉的差异：reward 字典 key 和权重都一样，但底层函数语义不同 —— 光对比权重表完全看不出来。

⚠base_height (+1.5 两边相同)

GO2: base_height = square(z − 0.47) —— 平方惩罚函数配了正权重，实际在奖励偏离 0.47(疑似 IsaacGym 移植 bug)。

LITE3: handstand_base_height = exp(−|z−0.39|·5) —— 正确的有界跟踪奖励。lite3 静默修正了这个坑。

⚠lin_vel_z (+0.2 两边相同) · 目标相反

GO2: lin_vel_x_penalty = square(vel_x) —— 奖励体 x 速度(鼓励运动)。

LITE3: handstand_lin_vel_z = exp(−|vel_x|·10) —— 抑制运动。同 key 同权重，objective 完全相反。

⚠ang_vel_xy (+0.2 两边相同) · 可能与指令冲突

GO2: 用 ang_vel_b[:2] = roll, pitch。

LITE3: 用 ang_vel_b[1:3] = pitch, yaw —— 正则了偏航轴，而偏航正是 ang_z 指令要跟踪的轴。疑似 bug：可能与偏航跟踪打架，建议核实。

◆feet_clearance · 行为级分叉(非笔误)

正弦抬腿奖励(+0.4)在 go2 作用于后摆动脚 (2,3)；在 lite3 改作用于前支撑脚 (0,1) —— lite3 把它当成支撑脚的踏步节律塑形。这是设计选择，但确实是行为分叉。
